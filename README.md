## Retire-and-replace logic

* **GUILTY:** blocked activity never executes; the original specialist court attempts a new compliant alternative. Research proposals must pass their court separately.
* **NOT GUILTY:** safe local draft and validation-plan generation can proceed automatically; **it is not permission to contact customers or upload listings**.
* **Not launched after 14 days:** retire as `UNLAUNCHED`, not market failure.
* **Genuinely launched, user-reported 100+ views and no clicks after 7 days:** retire for low engagement.
* **14 days launched without positive reported net results:** retire or mark inconclusive; choose a different technique.
* **Verified sales:** currently none; any figures you enter manually are marked `USER_REPORTED_UNVERIFIED`.

## v0.8.1 Windows SQLite lock fix
The v0.8 test `test_tamper_detection` held a SQLite connection open using a Python context manager which does not close sqlite3 connections, leading to WinError 32 during temporary-directory cleanup. v0.8.1 explicitly commits and closes the tampering fixture before cleanup, and explicitly closes read-only trend database handles.
